## 3.4 作业一评分标准

| 评分维度 | 分值 | 评分要求 |
|---|---:|---|
| 1. 评测实施与结果记录 | 25 | 能够按照要求完成Benchmark评测，记录任务描述、预期结果、实际结果及测试或评分结果；评测过程规范，结果判定依据明确，实验记录真实、完整、可追溯。 |
| 2. 运行轨迹记录与证据分析 | 15 | 能够保存完整的Agent运行轨迹，包括任务输入、执行步骤、工具调用及返回结果、最终输出等；能够从运行轨迹中提取与任务成功或失败相关的关键证据。 |
| 3. 深入错误分析（Error Study） | 30 | 能够结合实际运行轨迹定位问题发生的具体环节，区分错误现象、直接原因与深层机制；分析具有针对性和解释力，能够说明错误产生的条件及其对任务执行的影响。 |
| 4. 错误机制归纳与改进策略 | 20 | 能够归纳至少2类具有代表性的错误机制，分析其产生原因，并提出与错误成因相对应、具体可操作的改进策略。 |
| 5. 改进验证与报告质量 | 10 | 鼓励通过对照实验或小规模验证检验改进策略的有效性，并客观分析实验结果及局限性；报告结构清晰、论据充分、结论与证据一致。 |
| 总分 | 100 | |

评分说明保留原意：覆盖与最低数量为必做要求；重点考察分析深度，成功率高低不作为主要评分依据；原因需有轨迹或实验支持；将评测、定位、分析和策略联系起来；实验必须真实，未执行验证不得写成完成。

## 4.3 作业二评分标准

| 评分维度 | 分值 | 评分要求 |
|---|---:|---|
| 1. 问题定义与改进动机 | 15 | 能够基于作业一的评测结果和错误分析，准确定位Agent的关键问题，解释错误产生的原因，并提出目标明确、与问题相匹配的改进方案。 |
| 2. Agent改造与技术实现 | 25 | 完成至少1项实质性改造，具有真实、可验证的代码、配置或工作流变更；技术设计合理，能够解释核心机制及其作用原理，且改造与目标问题之间具有明确联系。 |
| 3. 对照实验与效果分析 | 25 | Baseline设置合理，实验条件具有可比性，测试规模满足要求；评测指标定义清晰，结果记录完整，能够客观分析改造前后的性能、成本与稳定性变化。 |
| 4. Error Study与消融分析 | 20 | 能够结合至少3个真实案例分析改进成功、持续失败或性能退化的原因；完成至少1组消融实验，并基于证据分析关键机制的实际作用及其局限性。 |
| 5. 可复现性与报告质量 | 15 | 提供完整的代码、配置、运行记录和实验报告；实验过程可追溯，结果与结论一致，对实验局限性、潜在副作用及改进贡献有清晰说明。 |
| 总分 | 100 | |

评分说明保留原意：评价问题定位、实质改造、合理实现及验证能力；强调与作业一的关联、公平比较及证据；区分实现与效果，性能未提升但分析严谨仍可获得合理成绩；代码、配置、轨迹、脚本和记录尽可能完整。

本文件记录教师评分标准，不是教师实际评分或自行估分。两表各五项分值之和均为100。
