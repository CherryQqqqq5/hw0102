# 公开验证与候选交付的独立确认协议 v2

研究对象是在固定执行预算内，公开验证、候选保存及截止前交付能否改善独立任务的最终结果。本协议与代码、题单、检查清单和运行计划在v2首次模型请求前一并提交；正式运行记录保存该提交号。30道任务的原始空解/上游参考控制全部通过，SWE与Terminal的最终公开检查均正确区分原始产物和参考产物。原384条评分和全部失败保留，新增结果单独统计。

v1已在首次请求前以6319dd7冻结，但在第7位置出现Python3.6区域设置导致的文件名解码错误，候选初始化在模型请求前失败。原题评分有效失败；同题正在运行的B0自然完成后停止队列。v1共8条评分，7通过/1失败，剩余262位置未启动，全部原记录与消耗保留。v2仅为候选文件助手设置UTF-8进程环境；题目、公开检查、提示、方法规则、模型、每题预算和顺序不变。原错误已在同一镜像复现，全部10个SWE镜像的初始化、非ASCII文件名保存和恢复均通过真实回归，模型请求为0。修复后完整重跑270位置，不复用v1有利成绩。v1的8条结果在本次修复前已可见，报告须披露该版本边界。详见`confirmation-locale-repair-v2.md`及原始证据。

## 题目与环境

三个基准各10道新题，共30道独立任务。候选排序种子为`nju-course-independent-confirmation-20261105-v1`。排除原45道题、历史trial记录中已暴露题及重复家族。SWE-bench Verified按Django、scikit-learn、xarray、pytest分配3、3、2、2题；Aider Polyglot按C++、Go、Java、JavaScript、Python、Rust分配2、2、1、2、2、1题。Terminal-Bench 2.1按类别轮转，类别内使用固定散列排序。全部候选和资格排除理由保留。

任务版本沿用原固定修订：SWE数据78f471bf655a3137b2e8a75af1501690ec009ec3，Terminal7131e4375048a0e408a8fb404b5f499d726b695b，Aider7e0611e77b54e2dea774cdc0aa00cf9f7ed6144f。每道题必须通过原始空解失败、上游参考通过的环境控制。上游参考只供环境和公开检查的工程验收，不进入模型提示或工具可读目录。检查编制仅使用公开题面、原可见测试及可见输入；隐藏评分条件继续由原评分器使用。

资源范围保持原隔离环境：本地Docker虚拟机4核、约5GB内存，网络关闭。SWE生成2核、3072MB，Aider生成1核、2048MB；Terminal使用原task.toml配置。正式生成及独立评分逐题顺序执行，不互相并发。原评分器的编译和评分时间独立记录。公开复现所需Django-12193 PostgreSQL表单依赖psycopg2-binary2.8.6、pytest-5631数组依赖NumPy1.23.5，以只读目录提供给三个条件。缺少Python的polyglot-rust-c为三个条件统一提供Python3.13独立运行时，供候选管理及公开检查执行；原Rust/C++编译器和原独立评分保持不变，准备耗时单列。

环境资格排除包括：原离线环境缺少任务必需外部资源、原参考在既有离线条件下不能通过，以及输入包含会被写入模型提示或日志的凭据形式数据。排除发生在首次模型请求前，不使用解题成绩。sanitization任务的原控制有效，但其输入包含凭据形式值，因此按输入边界排除；该有效控制仍保留。

## 三个条件

| 条件 | 相同部分与唯一开关 |
|---|---|
| B0 | mini-SWE-agent原生Bash决策和结束机制，共用CodeBuddy适配器及硬执行时限 |
| C0 | 公开检查说明、结构化验证入口、候选保存/恢复、剩余预算反馈；模型决定验证与交付时机 |
| C1 | 与C0完全相同的提示、检查和工具；额外启用程序安排验证、保存满足公开条件的版本及截止前交付 |

C0/C1通过`verify(check_id)`执行登记命令，保存退出码、完整输出、对应候选和检查依赖。成功证据在候选或依赖变化后失效，既有测试和未允许修改的输入发生变化时标记为`protected_dependency_changed`。公开检查范围由清单逐项声明；格式检查通过不能推出隐藏语义正确。

C1从第6次决策后开始，每隔至少2次决策，只在候选变化且存在待验证条件时自动检查。最近实测检查时间决定预留：`min(180,max(30,2.5*check_seconds+20))`秒。剩余时间不超过`max(180,2*reserve)`或剩余决策不超过4次时进入最终验证阶段，向模型提供失败反馈。剩余时间不超过`reserve+25`秒或已使用23次决策时结束探索并交付。

最终检查为恢复操作预留30秒（已有可行候选）或15秒（尚无可行候选）。当前候选未通过且验证依据未改变时，恢复最近保存的公开可行候选，并重新核对产物及依赖摘要。没有可行候选时，保留当前真实产物和未解决状态。候选操作失败也保留当前产物，仍由原评分器判定；这种实现失败计入正式结果。

## 模型和预算

CodeBuddy 2.179.3，模型标识`deepseek-v4.1-flash`；使用登录账户的既有额度。三组统一采用StructuredOutput传输，服务未提供可固定的采样种子。温度、服务端推理预算和模型版本别名的内部更新无法由该接口独立冻结，报告对此作限制说明。

每次任务最多24次决策、600秒执行、每条命令60秒。单次服务请求最长150秒；最多额外重试2次请求超时，并受剩余任务时间限制。重试沿用同一请求，不增加决策额度，实际请求次数及成本完整计算。模型等待、重试、命令、检查、摘要和候选保存均计入同一600秒；传输/终止进程允许记录实际清理开销，超出量如实报告。容器准备和独立评分另计。

通用配置中的`max_output_tokens=4096`未传递给CodeBuddy命令行，因此不视为实际输出词元上限。当前接口的硬限制是时间、决策数及单请求限制，输出词元按服务返回用量统计。费用返回值不等于账户账单。

## 顺序、停止与恢复

30题×3条件×3轮共270个位置。每题三轮采用循环顺序，让三个条件在第一、第二、第三位置各出现一次；任务按固定排序执行。完整顺序保存在`confirmation-plan-v2.json`，与v1相同。单工作进程执行，不按中途得分提前结束或扩大样本。

v1与v2累计尝试上限300。v1已使用8次，v2队列上限292次，包括270个预定位置和最多22次机械恢复；每个位置最多两次额外机械恢复。原题有效失败、超时后可评分的产物、格式错误、算法失败和控制器错误均进入分母，不为获得更好成绩而重跑。只有导致原评分缺失的外部服务、网络或环境机械故障，才在保存原尝试和原因后按原条件恢复。发现阻断机制执行的可复现接口缺陷时先停止，保留有效失败评分、完成修复回归，并在新版本请求前固定三个条件的完整替换范围，不能单独替换失分一组。重复修复仍失败或达到尝试上限时停止并报告缺口。上述v1整体停止与v2完整重跑按本段明确披露，不能将v1称为已完成确认或将其失败记为未评分。

运行计划记录题单、检查清单、执行代码的SHA-256（Secure Hash Algorithm 256-bit，256位安全散列）及模型版本；首次请求前提交Git记录。每份trial及交互日志记录对应协议提交。模型可读范围仅为任务容器；模型客户端没有任务文件读写工具，命令由外部隔离执行器执行。

## 统计和机制证据

主要比较为C1/B0，机制消融为C1/C0，信息条件贡献为C0/B0。报告三个基准的各30次结果、总体90次结果、每题三轮平均、改善/持平/退化任务数和三轮全过任务数。以任务为单位、按基准分层进行10000次配对bootstrap（自助重采样），种子20261104，保留同题重复结构，给出95%区间。类别结果与超时敏感性分析属于辅助描述；不把三轮当作90道独立题，不以事后选择的显著性阈值决定完成。

成本包括v1全部8次、v2全部正式与机械失败尝试的请求、响应、重试、输入/输出/缓存词元，生成、检查、评分及总体耗时。主比较只使用v2完整270条；`previous_attempt_usage`保存v1消耗，`all_attempt_usage`合计所有批次。展示相同预算上限与实际消耗的差别。控制器指标包括自动检查次数、失败反馈后不同候选通过的序列、最终版本有有效验证证据的比例，以及候选恢复次数。发生序列只能支持机制过程描述，因果贡献以同题匹配对照为依据。

至少三个真实案例分别分析成功修复、持续失败以及退化或额外成本。原探索性RP正向结果、A未复现结果及F负结果继续作为方法形成证据。完整新结果产生前，不把工程验证写为性能改进，不承诺正向或显著结果。
