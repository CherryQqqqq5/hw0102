## 改造与消融

| 配置 | 行为 |
|---|---|
| B0 原生基线 | 使用默认决策循环和提交处理 |
| BP 文字提示 | 提供同样的公开检查、交付路径与第六步说明 |
| A 时效消融 | 第六步探测交付文件，记录模型执行的公开检查，提交时沿用已有通过记录 |
| F 时效扩展 | 在 A 基础上核对依赖内容，使过期检查失效 |
| RP 阶段反馈 | 在 F 基础上加入语义验证提示和剩余预算反馈 |
| R 自动检查 | 与 RP 使用相同提示和控制，在中途及提交时自动执行待验证或过期检查 |

公开检查依据题面和初始仓库可见材料逐题编制，覆盖有限。最终成绩由独立的原题评分器给出。[智能体代码](../shared/course_eval/agent.py)、[验证状态实现](../shared/course_eval/verification.py)、[检查清单](configs/public-checks-v2.json)

## 正向案例与失败分析

- **查询优化**：同预算比较中 B0 通过五项、未通过速度验收；RP 与 R 六项全部通过。R 第三步保存初稿，第八步完成优化与输出核对，第十步提交。该题支持整个改造的正向效果，RP 同样通过，因此不能单独归因于自动检查。
- **调度约束**：修订运行的 B0 使用13种全局形状，超过8种上限；RP 使用7种形状并通过全部六项验收。R 的格式检查通过，但运行成本仍超限。
- **相同补丁的提交开销**：`scikit-learn-14496` 的 B0/RP/R 补丁逐字节相同且均通过，分别使用9/15/8次请求，总耗时187.8/349.2/160.5秒。R 自动执行40项公开测试后提交；RP 两次被未登记检查阻止。
- **地址提取**：六题开发运行中 R 通过原题两项验收，旧 B0/F 参考地址覆盖率为0%/66.67%，均未达到75%。该比较来自不同运行时段，只作为开发证据。
- **覆盖边界**：开发运行的 xarray 中途公开检查通过，最终补丁仍未修复目标语义；pytest 原题通过，但候选修改了既有测试，另记为指令遵循错误。

详细步骤、原题输出及归因限定见[新增案例](evidence/revision-cases.md)。原方案的 Django 错误补丁、模型提取数值失败、超时敏感性删除范围见[原实验案例](evidence/improvement-cases.md)。
